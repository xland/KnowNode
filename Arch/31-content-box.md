# 31 · 容器区 ContentBox

## 定位

`UI/src/ContentBox/` **存放并展示页面的主要功能**，是界面的主体区域。

## 布局演变

| 阶段 | 列布局 |
| --- | --- |
| 原项目（老项目） | 三列：文章分类 / 文章列表 / 文章编辑器 |
| 现状（2026-10-08） | 三列：知识列表 `KnowList` / 知识节点网络画布 `KnowNet` / 知识节点详细内容 `KnowDetail`；**「文章」相关的组件与引用已全部删除** |
| 目标形态 | **已达成**。唯一更正：详细内容**不是**"点击节点后自动展开"——2026-10-07 改定为由容器右边缘的把手按钮手动展开／收起（见下） |

## 面板命名（已确定）

| 面板 | 类名 | 目录 |
| --- | --- | --- |
| 知识列表 | **KnowList** | `UI/src/KnowList/` |
| 知识节点网络画布 | **KnowNet** | `UI/src/KnowNet/` |
| 知识节点详细内容 | **KnowDetail** | `UI/src/KnowDetail/` |

> 三者沿用 `Xxx.html + Xxx.scss + Xxx.ts` 三件套约定。

## 目标布局

```
┌──────────────┬──────────────────────────┬──────────────────────┐
│  KnowList    │       KnowNet            │      KnowDetail      │
│  知识列表     │   知识节点网络画布         │  知识节点详细内容      │
└──────────────┴──────────────────────────┘
```

### 列 1：知识列表

- 由原来的「文章列表」改造而来。
- 列表项是**一个个"知识"**，例如：历史知识、编程知识、文学知识。
- **点击某个"知识"，画布就加载这个知识所包含的节点**（即列表与画布是「选哪个知识 → 显示哪张网」的关系）。

> 由此产生的重要概念：本项目存在「知识（Knowledge）」与「节点（Node）」两层——
> 一个知识是一张网的入口，节点是网中的个体。二者的数据关系待用户确认。

### 列 2：知识节点网络画布

- 由原来的「文章编辑器」位置改造而来。
- 用 **Konva** 实现，呈现节点 + 关联构成的网状画布。
- **画布细节待用户后续说明后再补充**（节点绘制、连线、缩放平移、交互等）。

### 列 3：知识节点详细内容

- **点击某个知识节点时，在右侧再展开一块区域**，显示该知识节点的详细内容。
- 呈现方式：**富文本编辑器**（不是只读展示，直接可编辑）。
- 实现：**roosterjs**，代码在 `UI/src/EditorBar/`（工具条）+ `UI/src/EditorContent/`（编辑区）。

## 详细内容的展开 / 收起（**2026-10-07 改定**）

> 原设计是「选中节点 / 连线时详情栏自动出现，取消选中就隐藏」。
> 用户改定：**选中不自动展开**，详情栏**默认收起**，由用户点按钮决定。

- 容器右边缘**垂直居中**有一个小把手按钮（`#detailToggle`，`icon` 图标）：
  - **收起时**图标为 `icon-expand-left`，贴在容器右边缘，点它展开详情栏；
  - **展开时**图标为 `icon-expand-right`，按钮挪到详情栏**左边缘外侧**（`right` = 详情栏宽度），点它收起。
  - 位置与图标由 `ContentBox.syncToggle()` 跟着展开状态与栏宽一起同步（与 splitter 同一套贴边逻辑）。
- **没有打开任何知识时按钮隐藏**（`visibility: hidden`）：既没有节点也没有"知识本身"可显示。
- 展开 / 收起由 `KnowDetail.toggle()` 切换，广播 `knowDetailExpanded` 事件让 `ContentBox` 重排 splitter 与按钮。
- 展开状态下切换对象（选中节点 / 连线 / 取消选中）→ 面板**内容跟着换**，不收起；
  收起时先把没落库的改动写完。

## 面板与分隔条（splitter）规则

### 三栏布局（2026-10-07 改定：**取消悬浮 / 钉住**）

> 原设计是「默认悬浮盖住画布、点图钉按钮才钉住成三列」。用户决定**不要悬浮态**：
> 详情栏就是三栏里的普通一栏，与 `KnowList`、`KnowNet` 并排。
> 由此作废：钉住按钮、`know_detail.pinned` 设置项、面板顶部的「详细内容」标题栏。

- **详情栏收起时隐藏**（不占宽度，画布吃掉剩余空间），由上面那个按钮展开／收起
  （**与"有没有选中节点"无关**——2026-10-07 起选中不再自动展开）。
- 隐藏与显示只是加 / 摘 `.show`（`display: none` ↔ `flex`），内容、宽度、未保存的改动都保留。

### 分隔条

- **知识列表 ↔ 节点画布**：中间有一条 splitter，可拖拽调节两者宽度。
- **节点画布 ↔ 详细内容面板**：详情栏左边缘有一条 splitter，可拖拽调节两者宽度
  （**详情栏收起时这条 splitter 也跟着隐藏**——没有可拖的东西）。
- **三个元素（列表、画布、详情栏）都有最小宽度**，拖拽时不得小于最小值。

```
收起（两栏 + 把手）             展开（三栏）
┌────────┬────────────┬┐    ┌────────┬───────┬┬─────────┐
│ 列表 ┊ │    画布     │▏│    │ 列表 ┊ │ 画布  │▏│  详情   │
└────────┴────────────┴┘    └────────┴───────┴┴─────────┘
        splitter         ▏= #detailToggle
```

## 现状实现（已泛化到三个 `Know*` 面板）

`ContentBox.ts` / `.scss` / `.html` 中已有 splitter 机制：

- `.splitter` 绝对定位（宽 4px，`cursor: ew-resize`），HTML 里用 `data-target` 指向它要拖动其右边缘的面板。
- 拖拽用 `pointerdown` + `document` 上的 `pointermove/pointerup`，拖动时给 `body` 加 `splitter-dragging`。
- 最小宽度写成 `ContentBox` 的静态常量，注释要求与各面板 scss 的 `min-width` 保持一致
  （`KNOW_LIST_MIN` / `KNOW_NET_MIN` / `KNOW_DETAIL_MIN` = 300 / 500 / 300）。

  —— **已不成立（2026-10-08）**：`ContentBox.ts` 只 `import` 并挂载

### 宽度（已确定）

| 元素 | 宽度 |
| --- | --- |
| `KnowList` | **最小 300px** |
| `KnowNet` | **最小 500px**，正常情况下占据剩余全部空间（弹性） |
| `KnowDetail` | **默认 600px**（2026-10-07 由 500 改定），最小 300px，拖拽时不得小于它 |

- 拖拽 splitter 时：`KnowList` 不得小于 300px、`KnowNet` 不得小于 500px、`KnowDetail` 不得小于其最小宽度。
- 三者最小宽度之和超出窗口宽度时（极端窄窗），以 `KnowList` → `KnowDetail` → `KnowNet` 的顺序保底，
  剩下的给不下面板时不强撑（拖拽被钳制在当前可用范围）。
