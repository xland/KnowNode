### 实现要点（Konva）

- 缩放/平移通过 `stage.scale()` + `stage.position()` 实现，是**视图变换**，不改节点的布局坐标。
- **滚轮分两用**（2026-10-07 改定）：**Ctrl + 滚 = 缩放**（以鼠标位置为锚点，光标下那个点缩放前后停在同一处）；
  **不按 Ctrl = 上下挪画布**（当滚动条用，与页面滚动同向：`deltaY > 0` 是"想看下面"，画布往上走）。
  触控板的捏合手势浏览器会带 `ctrlKey`，天然落在缩放这条分支上。
- `deltaMode` 折算：Firefox 常给「行」(1) 而不是像素(0)，按 `WHEEL_LINE_HEIGHT = 16` 折，
  一页 (2) 按视口高折——不然同一只鼠标在不同浏览器里快慢差好几倍。
- 打开一张知识时 `centerOrigin()` 把视口中心对到画布原点 `(0, 0)`。

## 新建知识的初始状态

> **原文"新建一个知识时，`KnowNet` 中只有一个『未命名』节点"是错的（2026-10-08 核对）**：
> `list.create` → `KnowList::add()` 只插 `know_list` 一行（外加它自己的那条 `know_detail`），
> **不建任何节点**——原生侧这一条从头到尾都没变。（这里原先还写着"因此画布是空的"，
> 见下面 2026-10-08 的更正。）
>
> **2026-10-08 更正**：节点由**前端**紧接着补上。`KnowList.create()` 在 `select()` 之后
> （`select()` 内部 await 完 `KnowNet.open(id)`）调 `KnowNet.createFirstNode(id)`，
> 在画布原点 `(0, 0)` 建第一个节点。因为 `open()` 末尾的 `centerOrigin()` 刚把视口中心对准了原点，
> 这个节点**正好出现在画布正中心**，并由 `adoptNewNode()` 选中它、直接进入标题编辑（focus + 全选），
> 用户敲完名字回车就完事。"新建知识 → 空画布 → 得先右键才建得出第一个节点"这一步没有了。

- 新建一个知识时，画布上**已经有 1 个「未命名」节点**：就在正中心，且处于标题编辑态。
- **「未命名」是新建节点的默认标题**（现在也确实是"新建知识时自动送的那个节点"的标题）：
  `node.create` 不传 `title`（或传空串）时由表类落库为「未命名」。
- 之后再添节点照旧：空白处右键 → 新建节点（建在右键处），或选中某节点后 `+` / Tab。

### 鼠标操作

| 位置 | 操作 | 行为 |
| --- | --- | --- |
| 节点**中间** | 拖拽 | **移动节点**（多选时整批跟着一起动） |
| 节点**边缘** | 拖拽 | **连线**：拖到另一节点上松手即建立关联；**在空白处松手 = 取消连线** |
| 节点 | 单击 | 选中该节点（只留它一个） |
| 节点 | **Ctrl + 单击** | **加选 / 取消这一个**（多选的第二种方式，2026-10-07 加） |
| 节点 | 双击 | **原地改标题**（直接编辑节点内文字，不弹对话框） |
| 选中节点后 | 点节点右侧 **`+` 小按钮** | 新建关联知识点（自动连线） |
| 选中节点后 | 按 **Tab 键** | 同上（与点 `+` 等效） |
| 选中节点 / 连线后 | 按 **Del 键** | **删除**选中的那些（多选 = 删这一批，2026-10-07 加） |
| 改标题时 | 按 **Tab 键** | 当前标题先落库，接着**新建关联节点并直接编辑它的标题**（连打，2026-10-07 加） |
| 画布空白处 | **按住 Ctrl 或空格 拖拽** | **平移画布**（2026-10-07 改定：都不按时拖不动画布） |
| 画布空白处 | 不按平移键拖拽 | **框选**：拉一个蓝框，与之交叠的节点一起选中 |
| 画布任意处 | **Ctrl + 滚轮** | **缩放画布**（2026-10-07 改定：不按 Ctrl 滚不缩放） |
| 画布任意处 | 滚轮 | **上下移动画布**（就是滚动条的用法） |
| **搜索框** | 输入标题片段 + **回车** | 命中**第一个**节点就把它摆到视口正中并选中（2026-10-07 加） |
| **搜索框** | 一个都没命中 | 浮一行提示「没有找到匹配的节点」，**2 秒后自己没** |
| 画布空白处 | 单击 | **取消选中**（连带关闭 `KnowDetail`） |

- `+` 小按钮**只在单选一个节点时出现**（多选时没有"那一个"，按钮不显示），位于该节点右侧。
- **平移键（2026-10-07）**：**Ctrl 与空格**等价，按住任一个拖空白 = 平移画布，
  代码里统一叫"平移键"（`panDown = ctrlDown || spaceDown`）。两个键分别跟踪，
  松了 Ctrl 但空格还按着时仍然保持平移态。
- **空格的特殊性**：空格是要打字的字符，所以**焦点在能打字的地方（input / textarea / 富文本，
  以及就地改标题）一律不接管**——那一下就是在输空格。接管时要 `preventDefault`：
  既不让页面滚动，也免得焦点停在某个按钮上时按空格把那个按钮点下去。
- **平移的状态反馈**：按住平移键时画布光标变成「抓手」，提示现在可以拖；松开即恢复。
  keyup 收不到时（切走窗口）由 `blur` 兜底复位（两个键一起清）。

### 搜索框（**2026-10-07 加**）

- 一个 **DOM 层**浮在 `KnowNet` **左上角**（`top: 8px` + `left: 10px`），`z-index: 4` 压在画布之上
  （画布是 `inset: 0` 且没给 z-index）。里面是文本输入框 + 一枚 `icon-search`（iconfont 自带，点它等效回车）。
- **只在加载了某个知识时才出现**：默认 `display: none`，`open()` 里加 `.show` 放出来，
  `clear()` 里摘掉——没有打开知识时搜无可搜，摆个框在那儿是噪音。
- **回车 = 搜索**：按标题**包含匹配**（大小写不敏感、前后空格不算数），取 `nodes` 里**第一个**命中的
  （就是库里取出来的顺序，没有别的排序）。命中后 `centerNode()` 把视口挪到它身上——
  **只改 `stage.position()`**，缩放不动、节点自己的 `x / y` 更不动——然后 `selectNode()` 选中它。
- **没命中**：`.knowNetTip` 浮一行「没有找到匹配的节点」，`TIP_DURATION = 2000` 之后自己没；
  连着搜两次会 `clearTimeout` 重开计时（只认最后一次）。tip 是 `pointer-events: none`，纯提示，不挡画布。
- 空输入不算搜索（等于没给条件）；`clear()` 时清空输入框并收掉 tip。
- 焦点在搜索框里时，画布的 Tab / Del / 空格快捷键都不生效（`typingFocus()` 已经挡住了）。

## 自动布局（**已作废** —— 原方案 C「力导向 + 权重决定弹簧长度」）

> **作废记录**：用户决定放弃力导向布局，改为用户手动拖拽摆放节点；同时删除权重属性。
> 本节以下内容仅作**历史记录**保留，不再作为实现依据。

节点位置**全部由布局自动计算**，多对多无向图不做人工分层/分列。

### 力的组成

| 力 | 公式（概念） | 作用 |
| --- | --- | --- |
| **斥力** | `F_rep ∝ 1 / d²` | 任意两节点互斥，避免重叠、把图铺开 |
| **弹簧引力** | `F_spring = k_spring × (d − L)` | 有连线的两节点被拉向**该连线的自然长度 L** |
| **向心力** | `F_center = k_center × (center − p)` | 把整体拉回画布中心，防止子图飘散 |
| **碰撞力** | 按节点圆角矩形尺寸（取外接圆半径） | 硬性防重叠 |

### `L`（弹簧自然长度）的档位映射 —— 权重如何接入

```
1. 取当前知识内【所有连线】的权重，降序去重 → 档位序列 w0 > w1 > … > wk-1
   （全局统一计算，保证同一权重在任何位置都得到同一个 L）
2. L_j = L_MIN + (j / max(1, k-1)) × (L_MAX − L_MIN)
   → 权重最高的档位 L 最小（最紧、最靠近），权重最低的档位 L 最大（最松、最远）
   → 相同权重 → 同一档位 → 同一个 L
3. 力导向逐边使用各自的 L，迭代到平衡
```

**为什么用档位而不是原始值**：`1000 / 10 / -100000` 这类取值下，线性映射会让除极端值外的所有边挤到同一个
`L`，图会炸开或挤成一团；对数映射处理不了负数和零。档位只保留用户真正在意的**相对顺序**，
任何极端取值都稳定。代价：权重的绝对差距不体现在距离上（1000 与 10 的差距，看起来和 10 与 9 一样）。

> **重要取舍（力导向固有）**：档位环绕布局能**精确**做到"相同权重距离完全一致"；
> 力导向做不到精确——弹簧只是把距离**拉向** `L`，实际距离还会被其它节点的斥力、其它边牵扯。
> 因此方案 C 下「权重相同 → 距离相同」是**趋势一致**而非数值相等。
> 缓解手段：提高弹簧刚度 `k_spring`、适度降低斥力，使实际距离更贴近 `L`。

### 参数草案（可调，需实测微调）

| 参数 | 建议初值 | 说明 |
| --- | --- | --- |
| `L_MIN` / `L_MAX` | 120 / 320 px | 最高权重档 / 最低权重档的弹簧长度 |
| 斥力强度 `k_rep` | 与节点尺寸联动，待实测 | 太小 → 节点重叠；太大 → 图摊得过开 |
| 弹簧刚度 `k_spring` | 偏大（让 `d` 更贴近 `L`） | 保证权重差异在视觉上体现得出来 |
| 向心力 `k_center` | 弱 | 只防飘散，不主导布局 |
| 速度阻尼 `velocityDecay` | 0.4 | 每步保留的速度比例，防止震荡 |
| `alpha / alphaDecay / alphaMin` | 1 / 0.0228 / 0.001 | `alpha < alphaMin` 即视为收敛，**停止计算** |

### 调度与交互策略

- **迭代调度**：在 `requestAnimationFrame` 里每帧推进 1 步；收敛后彻底停止计算（省 CPU）。
- **重新加热（reheat）**：新增/删除节点或连线、**修改权重**、切换知识、点「重新布局」时，
  把 `alpha` 重置（如 0.3~1）让布局重新演化。
- **动画过渡**：权重变化后靠 reheat + 逐帧插值平滑移动，禁止瞬间跳变。
- **钉住节点**：用户手动拖动过的节点设置 `fx/fy` **固定不动**，力导向只调整其余节点；
  是否需要「取消固定」入口待确认，钉住状态建议持久化。
- **确定性**：初始位置用**基于节点 id 的确定性伪随机**生成，保证同一知识每次打开布局一致；
  新建节点的初始位置放在其关联节点附近（小随机偏移），避免从画布中心飞入。

### 性能

- 个人知识工具，节点量级预计数百~数千：
  - < ~500 节点：两两直算 O(n²) 即可；
  - 更多：斥力用 Barnes-Hut 四叉树近似（`theta ≈ 0.9`），降到 O(n log n)。
- **实现选型建议**：只引入成熟的力布局库（如 `d3-force`，支持逐边 `distance`、碰撞、速度衰减、`alpha` 机制），
  不引整个 d3；**布局只算坐标，Konva 只负责按坐标绘制**，二者解耦。

## 知识点的结构：图（多对多）——本节为修正版，取代此前「父子层级 / 树形」的说法

> **修正记录**：此前记录为「一个知识由一个最初的知识点衍生、内部是父子树形结构」，
> 该说法**已作废**。正确结构如下。

- **`KnowNet` 可以有多个初始知识点**（不再只有一个根）。
  - **新建知识时会送一个「未命名」节点**（2026-10-08 改定，见「新建知识的初始状态」）：
    它建在画布正中心并直接进入标题编辑。原生侧 `list.create` **仍然不建节点**，
    这个节点是前端 `KnowNet.createFirstNode()` 补的；
  - 用户可以通过**右键菜单**在空白处继续增加新的节点（**建在右键处**）。
- **知识点与知识点之间是多对多关系**。
- **一个知识点可以关联到任意一个其他知识点**（不受层级限制）。
- **关联没有方向**：A 关联 B 与 B 关联 A 是同一条关系，连线上没有箭头、不区分起止。

### 建立关联的两种方式

| 方式 | 操作 |
| --- | --- |
| 新建关联节点 | 选中某知识点后，点击节点右侧的 **`+` 按钮**或按 **Tab 键** → 为它创建一个**关联知识点**（新建节点 + 自动连线） |
| 手动连线 | 通过**拖拽连线**的方式，把**已存在**的两个知识点连起来 |

### 由此产生的影响

- 数据结构是**图（Graph）**而非树：节点表 + 关系表（多对多）。
- 之前「新增子节点 → 自动连线」的表述改为「新建关联知识点 → 自动连线」。
- 之前围绕「父 / 子 / 主节点」的布局表述，应理解为**围绕某个中心知识点排布它的关联知识点**；
  由于是多对多，一个节点会同时出现在多个节点的关联圈上，布局需要重新定义（见待确认）。

> **概念澄清**：把权重映射为「每条边各自的弹簧自然长度」属于**力导向的原生用法**（标准力导向本就允许逐边设置
> 弹簧长度），**不是**上文所说的「混合方案」。上文「混合」指的是「力导向 + 档位同心圆强约束」两者叠加。

## 权重与布局的关系（**已作废** —— 权重属性已删除，原「已选定 C」不成立）

> **作废记录**：权重已从设计中删除（见上文「连线权重 —— 已删除」），本节保留为历史记录，不作为实现依据。

**技术上**：力导向布局**不依赖权重**也能工作——把所有边的弹簧自然长度设为同一个常数，
布局完全由拓扑结构决定（互相连接多、共同邻居多的节点自然聚拢）。

**但权重的意义不只是布局**：它是「两个知识点关联强弱」的表达，也是用户在 `KnowDetail`
里点击连线时编辑的内容。因此是否保留权重是**产品问题**，不是布局问题。

| 方案 | 布局 | 权重 | 后果 |
| --- | --- | --- | --- |
| A 去掉权重 | 纯力导向（弹簧长度恒定） | 不要 | 距离只反映拓扑，用户**无法手动调节亲疏**；连线的详细内容需改为其它内容（如关系描述文本） |
| B 权重只做数据、不参与布局 | 纯力导向（弹簧长度恒定） | 保留 | 用户能记录/编辑关联强度，但**视觉距离与权重不一致**（权重 1000 和 10 看起来一样近） |
| **C 权重参与布局（已选定）** | 力导向 + 逐边弹簧长度 L(权重) | 保留 | 权重越大越近，视觉与语义一致；`L` 用**档位法**映射以免疫 `1000 / 10 / -100000` 这类极端值 |

### 改标题与新建关联节点（**已定，2026-10-06**）

- **双击改标题用 DOM 输入框覆盖**（不用 Konva 内嵌输入）：Konva 没有输入控件，
  而且只有真的 `input` 才吃得到中文输入法的候选过程。
  输入框按当前缩放算出位置与大小（`getAbsolutePosition()` + 矩形宽高 × scale）盖在节点上；
  编辑期间**关掉画布平移**，回车 / 失焦 = 提交（空串回落到「未命名」），Esc = 放弃。
  写库后同步 `StatusBar`（详情面板里的标题框已移除，见 33）。
- **新建关联节点**（`+` 按钮 / Tab 两条路，行为一致）：
  新节点放在选中节点**右侧**（`x = 源.x + 源宽/2 + 新宽/2 + 60`，`y` 与源对齐），
  建完**立刻建一条连线**——「关联节点」= 节点 + 连线一起有；节点入库后即使连线没建成也留着（用户可再拖一次）。
  新节点建好即**选中并直接进入标题编辑**，用户可以马上敲名字。
- **抢键范围（Tab 与 Del 共用）**：只在「焦点不在任何输入控件（input / textarea / contenteditable）」时抢；
  在详情面板的编辑器或列表输入框里按 Tab / Del 仍走它们自己的行为（Del 是删字，不能变成删节点）。
- **Del 删除**：删选中的节点或连线，与右键菜单里那两条是同一个实现（`node.remove` / `line.remove`），
  不弹确认框——与右键菜单保持一致，删错靠「再建一个」或后续撤销（撤销未做）。
- **改标题时按 Tab = 连打**：先把当前标题**写完库再建**下一个——等这一下的原因是源节点的矩形宽度
  是写完库才更新的，不等的话新节点会按旧宽度摆位、可能压在源节点身上。
  建完由 `adoptNewNode()` 自己进标题编辑并 focus，于是可以一路"敲名字 → Tab → 敲下一个名字"。

### 拖拽连线（**已定，2026-10-06**）

- **与拖节点的分界**：矩形**边缘 6px**（屏幕上恒定，按缩放折算回本地坐标）算拉线热区，
  中间剩下的部分才是拖节点。悬停在热区上光标变十字，悬停在中间是「移动」光标。
- **拉的过程**：跟着指针画一条**蓝色虚线预览**（起点 = 源节点中心，与正式连线同一条路径）；
  指针底下的节点**高亮**表示「松手就连到它」。
- **松手的判定**：
  - 落在另一个节点上 → 建一条连线（`line.create`）；
  - 落在空白 / 拖回自己 / 这两个节点**已经连过**（A→B 与 B→A 都算） → **无声取消**，不提示。
- **实现要点**：Konva 的拖拽是在 `mousedown` 时认领的，所以在矩形（而不是整个 group，
  免得「+」按钮掺和）的 `mousedown` 里判定命中热区后**立刻关掉节点与画布的 `draggable`**，
  `dragstart` 里再兜一道 `stopDrag()`，`dragend` 里见到"正在拉线"就**不写 `node.move`**。
  松手监听挂在 `window` 上，拖到画布外面再松手也能收尾。

### 选中模型与右键菜单（**已定，2026-10-06；多选 2026-10-07 加**）

- **选中是一批而不是一个**：`selectedNodes: Set<number>`，单选就是里面只有一个。
  `soleNodeId`（派生）在**恰好选中一个**时才非 null——`KnowDetail`、`Tab`、`+` 按钮都只在单选时有意义。
- **Ctrl + 点节点 = 加选 / 取消这一个**（2026-10-07 加，多选的第二种方式）：`toggleNode(id)`
  在这批里就去掉、不在就加进来；全去掉就是"一个都没选中"。
  - 判定放在节点的 **`mousedown`** 而不是 `click`：拖起来之后 Konva 不补 click，
    "Ctrl 按住拖一下"也得先把这一个加进这批，才能带着整批一起走。
  - 所以 `click` 里见到 `ctrlKey` 必须**直接返回**——否则 mousedown 加完、click 又把它翻回去，等于没点。
  - 用事件自带的 `e.evt.ctrlKey`，不读自己的 `ctrlDown` 标志（那个跟踪有可能与真实按键不同步）。
  - Ctrl 命中**节点**时不走平移（Konva 命中的是 group，stage 那套平移不参与），两者不冲突。
- **框选**（2026-10-07）：不按 Ctrl 在空白处按下并拖出 >3px 即起框，矩形画在 `nodeLayer` 最上层、
  `listening: false`（不挡命中），线宽与虚线按缩放折算（屏幕上恒为 1px）。
  松手时**与矩形交叠**的节点都算选中（擦到一点就算，不要求整个框住）。没拖动就还是"点空白"，由 `click` 取消选中。
  Konva 在 mouseup 后还会补一个 `click`，所以框完选 / 平移完画布要置 `skipStageClick`，否则刚选中的立刻被取消。
- **`skipStageClick` 只在"这一次按下 → 抬起"之内有效**（2026-10-07 修）：拖完节点 Konva **不**补 click，
  标志却已被 `dragend` 置上（节点那次 dragend 会冒泡到 stage），于是一直挂着，把下一次点空白（本该取消选中）
  白吃掉一次——表现为"要点两下才取消"。所以：**`mousedown` 按下时先清一次**（任何残留一律作废），
  且 `dragend` 只在 `e.target === this.stage`（真的是平移画布）时才置位。
- **多选时的三件事**：
  1. **整批拖拽**：`dragstart` 记下整批基线，`dragmove` 按被拖那一个的位移带着其余节点走，`dragend` 对这一批逐个 `node.move`。
  2. **整批删除**：`Del` 键删 `selectedNodes` 全部；右键命中多选里的节点时菜单项变成「删除选中的 N 个节点」。
     删完只重画一次，并从选中集合里剔掉已删的（`removeNodes`）。
  3. **不展开 `KnowDetail`**：详情是给"某一个对象"用的，多选时关掉它，`StatusBar` 改显示「已选中 N 个节点」。
- **`render()` 之后要补回选中态**：形状是新建的，高亮（蓝边 + 单选的 `+`）会丢，
  所以重画末尾按 `selectedNodes` 再刷一遍——顺带修掉了以前"删个不相关的节点会让选中高亮消失"的问题。
- **按下未选中的节点先单选它**（`mousedown`）：不然拖的是个没选中的节点，看起来像多选失灵。
  按下的那个已在选中集合里则**保留整批**，交给 `dragstart` 一起拖。
- **节点与连线的选中互斥**：详情面板只有一个、`StatusBar` 也只有一行，
  所以选中一个就把另一个清掉（`selectNodes` / `selectLine` 互相调用对方的"空"）。
- **单击连线** → 选中它，连线描蓝加粗，`KnowDetail` 以 `line` 打开（只有详情、没有标题），
  `StatusBar` 显示**两端节点的标题**（`A ↔ B`，连线自己没有名字）。
  连线只有 2px 宽（2026-10-07 由 1px 改定），判定用 `hitStrokeWidth: 12` 放宽；单击要 `cancelBubble`，
  否则冒泡到 stage 会被当成"点空白"立刻取消选中。
- **右键**：命中连线 → 六项颜色 + 「删除连线」；命中节点 → 六项颜色 + 「删除节点」（多选时是
  「删除选中的 N 个节点」）；**命中空白 → 「新建知识节点」，就建在右键那个位置**。
  浏览器默认菜单一律 `preventDefault` 掉。
  （这里原先写着"命中空白 → 不弹菜单"，与代码不符——空白右键是建节点的主入口之一。）
  命中节点 / 连线时**先选中再弹菜单**（与 `KnowList` 一致），详情面板跟着换到被右键的那个对象上；
  空白处没有可先选的东西，直接弹。没打开任何知识时无处可建，不弹。菜单用通用的 `UI/src/Menu/Menu.ts`。
- **菜单里的颜色**（2026-10-07 加）：**一个菜单项里并排放六个颜色按钮**，不是六个菜单项。
  按钮本身就是图标：当前色 `icon-check`、其余 `icon-uncheck`，图标颜色就是那个颜色本身；
  **再点一次当前色的按钮 = 取消标记**，回到默认（写 `color = 0`）。
  `MenuItem` 为此多了可选字段 `colors`（`MenuColorButton[]`），给了它就画成一行按钮、不画文字。
- **选色即写库**：`node.color` / `line.color`，成功才改本地数据并重画（失败保持原样）。
- **颜色一律不加透明度**：节点填充直接用该颜色（半透明会让压在下面的连线从节点里透出来，很难看）；
  连线同理用原色。
- **选中态不能盖掉标记色**（2026-10-07 修正）：挑色时那条线正被选中着（右键先选中再弹菜单），
  若选中一律描蓝，刚挑的颜色就看不见了。现在的规则是——**没标记**时选中蓝 / 未选中灰；
  **标记了**就用标记色本身，选中时压暗一档（×0.75）当选中反馈。
- **删除的连带关系**：删节点时它身上的连线与详情由**库**处理（外键级联 + 应用层清详情），
  前端同步把本地 `nodes` 与相关 `lines` 一起过滤掉；删连线只删它自己，两端节点与详情都留着。
- **删除不做二次确认**（2026-10-06 定）：点菜单项即删，删知识同理（见 [34](./34-know-list.md)）。
- **右键空白处** → 「新建知识节点」，节点就建在**右键处**（先把屏幕坐标换算成画布坐标：
  `(clientX - 容器左上角 - stage.position) / stage.scale`）。
  没有打开任何知识时（`listId == null`）无处可建，不弹菜单。
  建好之后与「关联新建」共用同一段收尾（`adoptNewNode`）：进本地数据、重画、选中并直接进入标题编辑。

  引力沿用 FR 的 `d² / L`。
- 加了一个很弱的**向心力**（0.04）把整张图拉回原点，不然没连线的孤立节点会被斥力推得很远。
- 算完把**质心挪到原点**：画布约定是"视口中心对准画布原点"，只靠向心力挡不住整体漂移，
  不归位的话下次打开这张网就偏出视口了。
- **动画**：算完先用目标坐标 `fitPoints()` 把视口对准（终点已知，不用等节点滑到位），
  再 400ms 缓出把节点挪过去（Arch/32：禁止瞬间跳变），**落定后才统一写库**（一次 `node.move` 一个节点）。
- **确定**：从当前坐标出发；两点完全重合时按 id 派生确定的小偏移掰开，所以同一份数据每次整理结果一致。
