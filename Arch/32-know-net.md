# 32 · 知识节点网络画布 KnowNet

代码位置：`UI/src/KnowNet/`，用 **Konva** 实现。

## 画布缩放与全局视图

- 画布上节点可能很多，必须**允许用户放大 / 缩小 `KnowNet` 画布**，以便观察具体的知识节点。
- 在 **`KnowNet` 面板的右上角**放一个按钮：
  **点击后画布自动缩放到合适比例，把整张网的所有节点都展示出来**（一屏看全图）。

### 实现要点（Konva）

- 缩放/平移通过 `stage.scale()` + `stage.position()` 实现，是**视图变换**，不改节点的布局坐标。
- 「展示全部」按钮：计算所有节点的包围盒（bounding box），
  按 `min(视口宽 / 包围盒宽, 视口高 / 包围盒高)` 取缩放比（留少量边距），并平移使其居中。
- 缩放建议**以鼠标位置 / 视口中心为锚点**，避免视觉上"跑偏"。

## 节点（Node）的呈现

- 一个知识节点是一个**圆角矩形**。
- 矩形**中间有文字**，文字是**该节点的知识名称**（即节点详情里的「标题」，二者是同一份数据）。
- **高度固定，宽度按标题长度自适应**（宽度上限待定；标题本身最多 36 字符，见
  [33-know-detail.md](./33-know-detail.md)）。

## 连线（Link）的呈现

- 节点与节点之间用**贝塞尔曲线**连接。

## 节点、连线与详细内容的关系（核心规则）

- **点击知识节点** → 打开 `KnowDetail`，显示该节点的详细内容。
- **点击节点之间的连线** → 同样打开 `KnowDetail`。
- 即：**连线本身也对应一份详细内容**（不只是节点有内容，关系也有内容）。

> **已确认**（详见 [33-know-detail.md](./33-know-detail.md)）：详细内容确实同时挂在「节点」与「连线」两类实体上。
> 数据层需有**节点表**与**连线（关系）表**，二者各自持有标题/权重与富文本详情字段。

## 新建知识的初始状态

- 新建一个知识时，`KnowNet` 中**只有一个"未命名"节点**。

## 交互约定（已确定）

### 鼠标操作

| 位置 | 操作 | 行为 |
| --- | --- | --- |
| 节点**中间** | 拖拽 | **移动节点** |
| 节点**边缘** | 拖拽 | **连线**：拖到另一节点上松手即建立关联；**在空白处松手 = 取消连线** |
| 节点 | 单击 | 选中该节点 |
| 节点 | 双击 | **原地改标题**（直接编辑节点内文字，不弹对话框） |

| 选中节点后 | 按 **Tab 键** | 同上（与点 `+` 等效） |
| 画布空白处 | 拖拽 | **平移画布** |
| 画布任意处 | **滚轮** | **缩放画布** |
| 画布空白处 | 单击 | **取消选中**（连带关闭 `KnowDetail`） |

- `+` 小按钮**只在节点被选中时出现**，位于该节点右侧。

### 右键菜单

| 右键位置 | 菜单项 |
| --- | --- |
| **画布空白处** | **新建节点** |
| **节点上** | **删除当前节点** |
| **连线上** | **删除连线** |

### 节点与连线样式

- 节点：**高度固定**，**宽度按标题长度自适应**。
- 连线：**贝塞尔曲线**，**控制点按两节点的相对位置自适应**。
- **初始知识点没有视觉差异**（外观与普通知识点完全一致）。

## 关联节点与自动连线

- 用户为节点**新建关联知识点**后，两个节点之间**自动出现连线**（不需要单独的"连线"操作）。
- 因此建边方式之一是：**建节点即建边**；另一种是手动拖拽连线（见下文「知识点的结构」）。

## 连线权重（Weight）—— **已删除**

> **作废**：权重属性已从设计中删除（放弃自动布局后，权重失去作用）。
> 连线不再有权重；点击连线打开 `KnowDetail` 时**只有富文本详情**。

（以下为历史记录）

- **连线拥有权重属性**，语义是**两个知识点关联的强弱**。
- **权重越大，两个知识点离得越近**；权重越小，离得越远。
- **点击连线**，在 `KnowDetail` 面板中可以**修改这条连线的权重值**。
- 权重取值**不受约束**：用户完全可能把一个设成 `1000`、另一个设成 `-100000`、其余都是 `10`，
  即允许负数、允许量级差异极大、允许大量相同值。
- **新建连线时，权重默认初始值为 `10`**。
- **权重相同的连线：目标距离相同**（同一档弹簧长度，见方案 C）。

## 节点位置：用户手动拖拽摆放（**已确定**）

- **放弃自动布局（力导向）**，节点位置**由用户自己拖拽摆放**。
- 节点坐标需要**持久化**（`KnowNode.x / y`），见 [40-data-model.md](./40-data-model.md)。
- **权重字段随之删除**（权重原本的唯一作用就是驱动布局与距离，见下文作废说明）。

### 已确定的规则

| 问题 | 决定 |
| --- | --- |
| **新建节点的位置** | 放在**选中节点的右侧**（水平偏移，纵向对齐）。**允许盖住其它节点**——不做避让，用户自己会拖 |
| **新建知识的第一个「未命名」节点** | 放在**画布中心 / 视口中心**（二者对齐，见下） |
| **坐标系** | **允许负坐标**，画布不限边界 |

- 偏移取值草案：`x = 选中节点.x + 节点宽 + 间距`（如节点宽 160、间距 40 → `+200`），`y` 与选中节点相同。常量集中定义，可调。
- 「画布中心 = 视口中心」的实现方式：第一个节点坐标直接取 **`(0, 0)`**，打开知识时把视口居中到 `(0, 0)`
  （后续也可用「展示全部」按钮自动适配视口）。这样两个"中心"始终一致，无需区分。

### 「一键整理布局」按钮

- `KnowNet` **右上角保留两个按钮**：
  1. **展示全部**：自动缩放到一屏显示所有节点（已定）；
  2. **一键整理布局**：**仅在用户点击时**跑一次力导向布局（不做自动持续布局）。
- 整理结束后，**把结果坐标写回 `KnowNode.x / y` 持久化**（否则刷新即丢失）。
- 整理采用**纯拓扑力导向**（权重已删除 → 所有边**同一个弹簧长度**，即前述方案 A）：
  斥力 + 弹簧引力（恒定 `L`）+ 向心力 + 碰撞力，`alpha` 收敛即停。
  参数沿用 [32](./32-know-net.md) 中的力导向参数草案，`L` 取一个固定常数（草案 180px，可调）。
- 整理会**重排所有节点**（无 `pinned` 字段，不保留手动位置的优先级）——用户手动摆的位置会被覆盖，符合预期。

## 自动布局（**已作废** —— 原方案 C「力导向 + 权重决定弹簧长度」）

> **作废记录**：用户决定放弃力导向布局，改为用户手动拖拽摆放节点；同时删除权重属性。
> 本节以下内容仅作**历史记录**保留，不再作为实现依据。

节点位置**全部由布局自动计算**，多对多无向图不做人工分层/分列。

### 力的组成

| 力 | 公式（概念） | 作用 |
| --- | --- | --- |
| **斥力** | `F_rep ∝ 1 / d²` | 任意两节点互斥，避免重叠、把图铺开 |
| **弹簧引力** | `F_spring = k_spring × (d − L)` | 有连线的两节点被拉向**该连线的自然长度 L** |
| **向心力** | `F_center = k_center × (center − p)` | 把整体拉回画布中心，防止子图飘散 |
| **碰撞力** | 按节点圆角矩形尺寸（取外接圆半径） | 硬性防重叠 |

### `L`（弹簧自然长度）的档位映射 —— 权重如何接入

```
1. 取当前知识内【所有连线】的权重，降序去重 → 档位序列 w0 > w1 > … > wk-1
   （全局统一计算，保证同一权重在任何位置都得到同一个 L）
2. L_j = L_MIN + (j / max(1, k-1)) × (L_MAX − L_MIN)
   → 权重最高的档位 L 最小（最紧、最靠近），权重最低的档位 L 最大（最松、最远）
   → 相同权重 → 同一档位 → 同一个 L
3. 力导向逐边使用各自的 L，迭代到平衡
```

**为什么用档位而不是原始值**：`1000 / 10 / -100000` 这类取值下，线性映射会让除极端值外的所有边挤到同一个
`L`，图会炸开或挤成一团；对数映射处理不了负数和零。档位只保留用户真正在意的**相对顺序**，
任何极端取值都稳定。代价：权重的绝对差距不体现在距离上（1000 与 10 的差距，看起来和 10 与 9 一样）。

> **重要取舍（力导向固有）**：档位环绕布局能**精确**做到"相同权重距离完全一致"；
> 力导向做不到精确——弹簧只是把距离**拉向** `L`，实际距离还会被其它节点的斥力、其它边牵扯。
> 因此方案 C 下「权重相同 → 距离相同」是**趋势一致**而非数值相等。
> 缓解手段：提高弹簧刚度 `k_spring`、适度降低斥力，使实际距离更贴近 `L`。

### 参数草案（可调，需实测微调）

| 参数 | 建议初值 | 说明 |
| --- | --- | --- |
| `L_MIN` / `L_MAX` | 120 / 320 px | 最高权重档 / 最低权重档的弹簧长度 |
| 斥力强度 `k_rep` | 与节点尺寸联动，待实测 | 太小 → 节点重叠；太大 → 图摊得过开 |
| 弹簧刚度 `k_spring` | 偏大（让 `d` 更贴近 `L`） | 保证权重差异在视觉上体现得出来 |
| 向心力 `k_center` | 弱 | 只防飘散，不主导布局 |
| 速度阻尼 `velocityDecay` | 0.4 | 每步保留的速度比例，防止震荡 |
| `alpha / alphaDecay / alphaMin` | 1 / 0.0228 / 0.001 | `alpha < alphaMin` 即视为收敛，**停止计算** |

### 调度与交互策略

- **迭代调度**：在 `requestAnimationFrame` 里每帧推进 1 步；收敛后彻底停止计算（省 CPU）。
- **重新加热（reheat）**：新增/删除节点或连线、**修改权重**、切换知识、点「重新布局」时，
  把 `alpha` 重置（如 0.3~1）让布局重新演化。
- **动画过渡**：权重变化后靠 reheat + 逐帧插值平滑移动，禁止瞬间跳变。
- **钉住节点**：用户手动拖动过的节点设置 `fx/fy` **固定不动**，力导向只调整其余节点；
  是否需要「取消固定」入口待确认，钉住状态建议持久化。
- **确定性**：初始位置用**基于节点 id 的确定性伪随机**生成，保证同一知识每次打开布局一致；
  新建节点的初始位置放在其关联节点附近（小随机偏移），避免从画布中心飞入。

### 性能

- 个人知识工具，节点量级预计数百~数千：
  - < ~500 节点：两两直算 O(n²) 即可；
  - 更多：斥力用 Barnes-Hut 四叉树近似（`theta ≈ 0.9`），降到 O(n log n)。
- **实现选型建议**：只引入成熟的力布局库（如 `d3-force`，支持逐边 `distance`、碰撞、速度衰减、`alpha` 机制），
  不引整个 d3；**布局只算坐标，Konva 只负责按坐标绘制**，二者解耦。

## 知识点的结构：图（多对多）——本节为修正版，取代此前「父子层级 / 树形」的说法

> **修正记录**：此前记录为「一个知识由一个最初的知识点衍生、内部是父子树形结构」，
> 该说法**已作废**。正确结构如下。

- **`KnowNet` 可以有多个初始知识点**（不再只有一个根）。
  - 默认情况下系统为用户创建**一个「未命名」知识点**；
  - 用户可以通过**右键菜单**增加新的**初始知识点**。
- **知识点与知识点之间是多对多关系**。
- **一个知识点可以关联到任意一个其他知识点**（不受层级限制）。
- **关联没有方向**：A 关联 B 与 B 关联 A 是同一条关系，连线上没有箭头、不区分起止。

### 建立关联的两种方式

| 方式 | 操作 |
| --- | --- |
| 新建关联节点 | 选中某知识点后，点击节点右侧的 **`+` 按钮**或按 **Tab 键** → 为它创建一个**关联知识点**（新建节点 + 自动连线） |
| 手动连线 | 通过**拖拽连线**的方式，把**已存在**的两个知识点连起来 |

### 由此产生的影响

- 数据结构是**图（Graph）**而非树：节点表 + 关系表（多对多）。
- 之前「新增子节点 → 自动连线」的表述改为「新建关联知识点 → 自动连线」。
- 之前围绕「父 / 子 / 主节点」的布局表述，应理解为**围绕某个中心知识点排布它的关联知识点**；
  由于是多对多，一个节点会同时出现在多个节点的关联圈上，布局需要重新定义（见待确认）。

> **概念澄清**：把权重映射为「每条边各自的弹簧自然长度」属于**力导向的原生用法**（标准力导向本就允许逐边设置
> 弹簧长度），**不是**上文所说的「混合方案」。上文「混合」指的是「力导向 + 档位同心圆强约束」两者叠加。

## 权重与布局的关系（**已选定 C**）

**技术上**：力导向布局**不依赖权重**也能工作——把所有边的弹簧自然长度设为同一个常数，
布局完全由拓扑结构决定（互相连接多、共同邻居多的节点自然聚拢）。

**但权重的意义不只是布局**：它是「两个知识点关联强弱」的表达，也是用户在 `KnowDetail`
里点击连线时编辑的内容。因此是否保留权重是**产品问题**，不是布局问题。

| 方案 | 布局 | 权重 | 后果 |
| --- | --- | --- | --- |
| A 去掉权重 | 纯力导向（弹簧长度恒定） | 不要 | 距离只反映拓扑，用户**无法手动调节亲疏**；连线的详细内容需改为其它内容（如关系描述文本） |
| B 权重只做数据、不参与布局 | 纯力导向（弹簧长度恒定） | 保留 | 用户能记录/编辑关联强度，但**视觉距离与权重不一致**（权重 1000 和 10 看起来一样近） |
| **C 权重参与布局（已选定）** | 力导向 + 逐边弹簧长度 L(权重) | 保留 | 权重越大越近，视觉与语义一致；`L` 用**档位法**映射以免疫 `1000 / 10 / -100000` 这类极端值 |

## 已确定

- **删除节点时，连带删除它的所有连线，以及对应的 `KnowDetail` 记录**（是）。
- **`is_initial` 字段已从数据模型中删除**：数据库不再区分"初始知识点"与普通节点
  （初始知识点只是交互上的说法——用户在空白处处右键新建的节点、或新建知识时的第一个节点）。
